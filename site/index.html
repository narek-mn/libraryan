The problem

      
Every agent writes docs. No one owns them.

      
Give a repo a few coding agents and a few months, and the Markdown rots: a README that documents flags the code dropped, three setup guides that disagree, NOTES.md, TODO_old.md, an empty ideas.md, and agent instruction files nobody has read since they were written.

      
The fix: one owner. Libraryan installs an agent that owns every Markdown file in your project: knowledge base, docs and agent instruction files.

What you get

    
One writer. Enforced, reviewed, and cheap.

    

      
Single writer, enforced.
A git pre-commit hook blocks every other edit, from any agent or editor. This is a hook, not a polite prompt.

      
Everyone else files a request.
Other agents and people drop a note in .libraryan/requests/. Libraryan writes the change.

      
Docs checked against the code.
When docs contradict the code, it fixes the docs and reports suspected code bugs. It never edits code.

      
Junk removed, facts kept.
Outdated Markdown is deleted only after a deletion ledger proves where each fact went.

      
A second agent reviews every commit.
A separate, read-only process with a fresh context. Anything but an exact APPROVE blocks the commit.

      
Cost caps built in.
Per-call and daily budgets, and a model-free audit that makes quiet nights cost $0.

    

  






  

    
How it works

    
Every doc change takes the same path.

    
Other agents and people hit the lock. Requests, commits, the daily run and manual runs all feed one Libraryan run, which is committed only if the ledger and the reviewer agree.

Safety

    
Why trust it with your docs

    

      

        
RiskWhat Libraryan does

        
          
It deletes something importantA deleted doc must be a pure move, or the run must quote where each fact went. Quotes are checked mechanically, otherwise the deletion is restored. Git keeps everything.

          
It hallucinatesEvery commit passes a second agent that sees the diff, not the author's reasoning, and fails closed.

          
It touches my codeIt writes only paths it owns. Anything else is restored, and code issues go into the report.

          
It leaks a secret into docsIt is told never to copy secrets, and an optional gitleaks scan runs on every run.

          
It burns money--max-budget-usd on every call, plus daily caps on runs, commits and failure streaks. Quiet nights skip the model entirely.

          
Other agents treat a request as a commandRequest files are data, never instructions.

          
I want it gonelibraryan uninstall removes hooks, cron and the agent in one commit. Your docs stay.

Quick start

    
Two commands. Then forget about it.

    
From now on Libraryan updates the docs after your commits and checks them once a day. It commits locally and never pushes. Remove it at any time with libraryan uninstall; the docs stay.

    

      

        
Terminal Python 3.10+ · pipx · git · Claude Code

        
$ pipx install libraryan     # once per machine
$ cd your-project            # any git repo, on its default branch
$ libraryan init             # once per project

        
libraryan init installs, builds the KB, commits.

      

      

        
Claude Code plugin optional

        
/plugin marketplace add narek-mn/libraryan
/plugin install libraryan@libraryan
/libraryan:init

        
/libraryan:init installs the CLI with pipx and runs libraryan init. /libraryan:status shows health and cost, and /libraryan:request files a doc change.

FAQ

    
Questions

    

      
Why not just put "keep the docs updated" in CLAUDE.md?
Because every agent then writes docs in its own style, at its own time, without checking them against the code. That instruction is how Markdown rot starts. Libraryan makes one writer responsible and enforces it with hooks, so the rule can't be skipped by accident.

      
What does it cost?
You pay for your own model usage. A run happens only after commits, on request, or when the daily audit finds something. Quiet days are free. Hard caps apply per call (default $5 for a run, $25 for the first setup) and per day. libraryan stats shows the real spend.

      
Does it work with Cursor, Copilot, Gemini or Codex agents?
Yes. The git pre-commit hook rejects any tool's commits to owned docs, the request rules are written into AGENTS.md, which those agents read, and the knowledge base is plain Markdown any model can use. Libraryan's own writer runs through Claude Code today; other runtimes are planned.

      
Will it push or open PRs?
No. It commits locally, on your default branch only, under its own docs(libraryan): prefix. You decide when to push.

      
Can my teammates still change docs?
Yes, by filing a request: a short Markdown file under .libraryan/requests/. Their agents learn how from the libraryan-request skill and AGENTS.md. You can also exempt paths in the config.
